The Partition Problem

A fundamental challenge in computational complexity and number partitioning.

Problem Definition

The Partition Problem is a fundamental challenge in computer science: Given a multiset S of positive integers, can it be split into two subsets S₁ and S₂ such that the sum of elements in each subset is identical?

Decision Question: Does there exist a subset S₁ such that Sum(S₁) = TotalSum / 2?

Example 1: Perfect Partition

Set S = {3, 1, 1, 2, 2, 1} | Total Sum = 10 | Target = 5

3 2
1 1 2 1

Result: YES

Example 2: Impossible Partition

Set S = {1, 2, 3, 5} | Total Sum = 11 | Target = 5.5

1 2 3 5

Result: NO (Odd sum 11 cannot be split equally into integer subsets)

NP-Completeness

1. Verification (In NP)

Partition is in NP because given a certificate (the subset S₁), we can verify it in polynomial time O(n). We simply iterate through S₁ to compute its sum and compare it to half of the total sum of S.

NP (Complexity)

Problems solvable by a non-deterministic machine in polynomial time.

Certificate

A candidate solution (like a subset) provided as proof to a verifier.

Verifier

A polynomial-time algorithm that checks if a certificate is correct.

2. Reduction from Subset Sum

We can prove Partition is NP-Hard by reducing the Subset Sum problem to it. Given a Subset Sum instance (S, t), we want to know if any subset of S sums to t.

Reduction

A method of proving problem B is at least as hard as A by showing that any algorithm for B can solve A.

To convert this to a Partition instance, we add one extra element b to the set S:

b = sum(S) - 2t

If b > 0, the new set S' = S ∪ {b} has a total sum of 2 · (sum(S) - t). A valid partition of S' will result in two subsets each summing to sum(S) - t. One of these subsets must contain b; removing b from that subset leaves a subset of the original S that sums exactly to t.

Worked Example:
Subset Sum Instance: S = {3, 1, 1, 2, 2, 1}, Target t = 9.
1. Sum(S) = 10.
2. Calculate adjustment b = |Sum(S) - 2t| = |10 - 18| = 8.
3. New set S' = {3, 1, 1, 2, 2, 1, 8}. New Total = 18. Target Partition = 9.
4. A partition of S' is {8, 1} and {3, 1, 2, 2, 1}. Both sum to 9.
5. The subset {3, 1, 2, 2, 1} sums to 9, which solves the original Subset Sum instance.

Dynamic Programming

If the numbers are small (or the target sum is small), we can use Dynamic Programming. This approach builds a table to determine if various sums are achievable using subsets of the given numbers. Here, dp[i][s] is true if a subset of the first i elements can sum to s.

DP Recurrence

dp[i][s] = dp[i-1][s] || dp[i-1][s - num[i-1]]

Karmarkar-Karp Heuristic (Largest Differencing)

The Karmarkar-Karp heuristic is a powerful greedy approach for the Partition Problem. It works by repeatedly taking the two largest numbers and replacing them with their difference.

Comparison of Approaches

Compare how different algorithms handle the same input in real-time. Notice how complexity scales as n grows.

Brute Force: Guarantees an exact solution by checking all 2ⁿ subsets. Becomes unusable quickly as n increases.

DP: Guarantees an exact solution. Fast for small numbers, but "pseudo-polynomial" — it fails if the total sum is very large.

K-Karp: A heuristic that doesn't guarantee the best answer but runs in O(n log n). Highly efficient for massive datasets.
